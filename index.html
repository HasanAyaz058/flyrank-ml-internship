Content Opportunity Scoring

A decision-support approach for prioritizing pages for human content-refresh review.

Abstract

Question: Can search and content signals be used to prioritize web pages that may deserve human review for a possible content refresh?

Method: I framed the problem as a content-opportunity scoring task, using search-performance and content signals and comparing a transparent baseline with machine-learning models.

Validation: The model audit emphasized an honest grouped/time-aware validation design, feature-leakage checks, and cautious interpretation of a future-performance proxy label.

Result: In the observed ML comparison, Logistic Regression achieved an average precision of 0.227, compared with 0.216 for Random Forest.

Interpretation: The result supports using the score as a directional prioritization signal and decision aid, not as proof that a refresh will improve rankings, traffic, or SEO performance.

1. Introduction / Problem Statement

Content teams can have many pages that could potentially be reviewed, but reviewing every page with the same priority is inefficient. This project asks whether available search and content signals can help identify which pages should be looked at first.

The practical output is a ranked review queue. A high score means a page deserves earlier human attention; it does not mean that the page definitely needs a refresh.

Scope: This is decision support. It is not an automated content editor and it is not a model of Google's ranking algorithm.

2. Data

The work uses the FlyRank ML Internship dataset and its search/content-performance signals. The analysis is deliberately described at a public-safe level.

  • Impressions, clicks, CTR, and average position.
  • Content age/staleness and days since last update.
  • Word count and search-demand context.
  • Changes in search performance.

What was excluded

Client names, domains and private URLs, raw private queries, credentials, and other identifying production information are excluded from this public artifact.

Release and time window

The analysis follows the approved FlyRank internship dataset/release and the analysis windows defined in the supporting notebooks. Private client-level identifiers and queries are intentionally not reproduced here.

3. Methodology

Prediction / ranking objective

The supervised task uses a future-decline proxy: whether a page's later impressions fall below a defined fraction of its current-period impressions. This is a measurable future outcome, not a causal label for whether refreshing a page would work.

Features

Candidate features included content age/staleness, days since last update, impressions, average position, CTR, word count, search-volume context, and recent search-performance signals. Features were required to be knowable at the decision moment.

Baseline and models

A transparent Week-4 baseline rule provided the simple reference approach. Week 5 compared it with Logistic Regression and Random Forest. Logistic Regression was retained as the preferred ML model because it had the higher observed validation average precision.

Validation and leakage

The model was audited using a more honest split, including grouping by client where appropriate, reducing the chance that the same client's patterns appear across both training and validation data. Future-looking or label-derived variables are leakage risks and should not be prediction features.

5. Limitations & Honest Framing

  • The score is a directional prioritization signal, not a guarantee of future decline.
  • The future-decline proxy is not a causal measure of refresh success.
  • A high score does not prove that editing a page will increase rankings, clicks, or traffic.
  • Reason codes identify measurable review cues; they are not causal explanations.
  • Validation results apply to the tested data and split and are not universal performance guarantees.
  • Seasonality, search demand, competition, algorithm changes, and measurement noise can affect observed performance.
  • Editorial, legal, strategic, and business context still requires human judgment.

Human-review boundary

The system should not automatically rewrite, publish, delete, merge, prune, or otherwise change content. It should not claim that an action will increase rankings or traffic. A human should review the page, evidence quality, search intent, and business context before any change.
